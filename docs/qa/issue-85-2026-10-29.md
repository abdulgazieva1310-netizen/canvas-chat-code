## Acceptance coverage

| Requirement | Implementation and evidence |
| --- | --- |
| Explicit consent | Existing capture requires an unchecked per-interview opt-in and explicit start action. Upload checks consent twice. New grants remain active-session-only; withdrawal is now also allowed after ending. Voice transcription and camera preview do not grant storage consent. |
| Storage and retention rules | Policy documents private owner-scoped local files, format/size/count limits, a fixed 30-day expiry and the existing minute-based reaper. Listings and downloads now enforce expiry independently of file-cleanup success. Delayed physical cleanup is explicitly distinguished from access expiry. |
| User deletion controls | Individual deletion and consent withdrawal revoke metadata/access immediately and queue failed physical removals durably. Regression tests simulate unavailable storage, verify 404 playback and preserved reports, then run cleanup successfully. |
| Relationship to saved interviews | Policy distinguishes optional recording bytes from persistent transcript/report data. Existing tests cover interview deletion, owner-only access and account cleanup. Ending does not grant new consent, and a pending consented final upload may finish. |
| Expired/deleted playback | Report playback clears/revokes its blob URL on expiry or disappearance. A missing recording refreshes metadata and preserves the report. Already-deleted responses are handled as a refreshed list. Tests cover expiry, deletion, repeated deletion and missing playback. |

## Boundaries

Tests use synthetic recording bytes and mocked browser media APIs. They verify
lifecycle/access behavior, not real-device microphone or codec quality. Storage
outages and application downtime can delay physical erasure; server access
still ends at expiry/deletion. Cleanup retries require a running application.
External backups and previously downloaded browser/user copies are outside
application recall. Video recording remains unsupported; the policy defines
requirements before enabling it. No database migration or new dependency is
required; deletion reuses the existing durable cleanup queue.

See [recording consent, retention and playback](../recording-consent-retention.md)
and the media endpoint contracts in `openapi.yaml`.
